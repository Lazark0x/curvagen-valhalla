# Valhalla 3.7.0 → 3.8.2 delta — perf changes, rebase conflict surface, config knobs

_R1 research (curvagen wayfinder map #66 — latency optimization). 2026-07-15._
_Sources: local git in `curvagen-valhalla/valhalla` (upstream tags 3.7.0 & 3.8.2 present), upstream `CHANGELOG.md`, upstream PRs._

## TL;DR

1. **Conflict surface = 6 files, all small upstream churn** (largest ~90 lines, in the offline `mjolnir/util.cc`). The v3 heart `route_action.cc` got only **+19 / -7** upstream. Recommend `git rebase --onto 3.8.2` with `git rerere` on. Risk: **LOW–MODERATE.**
2. **Tile compatibility: existing 3.7.0-built Balkans tiles LOAD on a 3.8.2 engine.** `GraphTileHeader` is size-stable — `kEmptySlots` 11→10 absorbs the new `boundingcircles_offset_`, so `sizeof` is unchanged (spare-slot discipline). Old tiles simply report `has_bounding_circles()=false`. **No forced rebuild to keep serving.**
3. **The whole delta contains exactly ONE serving-latency free-win: bounding circles for faster loki candidate search** (#5103 / #6141). It is **baked into tiles at build time**, so realizing it **requires rebuilding the Balkans tiles on 3.8.2**. No thor / bidirectional-A\* / sif-costing serving speedups upstream (the only `perf()` commit is a costmatrix `std::set → ankerl::unordered_dense::set` swap, #6013 — off our `/route` path).

**Framing for the map:** rebasing to 3.8.2 is *not itself* a latency win. It **unlocks** one lever (bounding circles), and that lever costs a tile rebuild. Manage the ledger's expectations accordingly.

Biggest upstream churn overall (informational): docs/openapi (1956), `mjolnir/graphtilebuilder.cc` (+379/-264), python bindings (large), **`loki/search.cc` (+246/-18)**, **`loki/tile_action.cc` (+220/-48)**, **`baldr/boundingcircle.cc` (+166, NEW)**, **`loki/tiles.h` (+204)**, `midgard/util.cc` (+202). The loki/baldr cluster is the bounding-circle feature.

## Axis 2 — Rebase conflict surface (feeds K1)

Conflict = {files the fork changed vs 3.7.0} ∩ {files upstream changed 3.7.0→3.8.2}. Exactly **6 files**:

| File | Upstream churn | Fork role | Risk |
|---|---|---|---|
| `proto/descriptors/options.proto` | +7 / -1 | fork appended round-trip option fields | **LOW** — append; watch proto field numbers vs new upstream fields (`dataset_id` etc.) |
| `src/mjolnir/util.cc` | +43 / -49 | tile-build util (offline) | **MODERATE** — only bites if rebuilding tiles |
| `src/thor/route_action.cc` | +19 / -7 | **v3 heart** (defect-gated construction, xcand) | **LOW–MOD** — small upstream hunks reapplied atop the fork rewrite; re-verify v3 gate after |
| `src/worker.cc` | +22 / -32 | request dispatch / action wiring | **MODERATE** |
| `test/CMakeLists.txt` | +0 / -2 | test registration | **TRIVIAL** |
| `valhalla/sif/dynamiccost.h` | +11 / -1 | costing base; fork added virtual hooks | **MODERATE** — watch vtable / interface signature drift |

Fork-**new** files (no conflict possible): `thor/roundtrip_expansion.{cc,h}`, `thor/worker.{cc,h}`, `thor/CMakeLists.txt`, `sif/motorcyclecost.cc` (fork-changed but upstream untouched in range), `test/curvature_metric.cc`, all `test/gurka/test_motorcycle_*`, `test/gurka/test_roundtrip_distinctness.cc`, all `tools/loopqual/*`, `Dockerfile.local`, CI workflow.

**Strategy recommendation:** `git rebase --onto 3.8.2 3.7.0 curvature-costing` with **`git rerere` enabled** — the repeated `route_action.cc` / `dynamiccost.h` hunks then auto-replay across the 52 commits after the first resolution. Fall back to a single `git merge 3.8.2` only if one file thrashes badly (fork force-pushes its remote anyway, so linear history is preferred). After rebase, K1 acceptance = full `Dockerfile.local` build + gurka round-trip suite + `loopqual` gate green.

**Tile-compat sub-finding (drives K1):** header is size-stable (see TL;DR #2), so **boot the 3.8.2 engine on the *existing* Balkans tiles first** — it should serve unchanged. `checksum_` was repurposed (#6123: build-id in high bits, 48-bit per-tile hash in low bits); if per-tile gzip checksum validation is enabled it could false-mismatch, but the Balkans extract is a plain tile dir → low risk. `date_created_` was removed from the header (#6115) — subsumed by the same size-stable repurpose.

## Axis 3 — New / changed config knobs & build flags

- **REMOVED** `thor.max_reserved_locations_costmatrix` help text (live key is `thor.costmatrix.max_reserved_locations`) — costmatrix, not our path.
- **ADDED** `dataset_id` tile config (#6126) — offline tile metadata.
- **ADDED** `valhalla_build_extract --region` / multiple `--region` args (#5964, #6172) — **R2 relevance**: build Balkans as a region extract; also the mechanism to produce **BC-enabled tiles** on 3.8.2.
- **ADDED** `lz4` OSM-PBF support (#6081); made optional system dep (#5993) — build input.
- **Bounding-circle enablement:** `search.cc` gates on `has_bounding_circles()`; **R2 must confirm** whether any config/request flag is needed to make `/route` correlation use the BC path (changelog names only `/locate` + `/tile` as "enabled").
- **REMOVED** `json`/jsonp request param (#6099) — we use plain JSON, no impact.
- Tile-header semantics (`date_created_` removed #6115, `checksum_` repurposed #6123) — see Axis 2.

## Handoffs

- **R2 (config / tile-locality):** cost the **Balkans 3.8.2 tile rebuild** as the bounding-circle-enabling lever; confirm the BC `/route` enablement knob; evaluate `--region` extract packaging.
- **P1 (profile):** measure the **loki correlation** stage on 3.8.2 with BC-rebuilt tiles vs old tiles to quantify the one free-win, and confirm `/route` correlation invokes the BC-accelerated candidate lookup.
