# Round-trip v4 — the build: what shipped, where it lives, and how it is checked

- **Ticket:** [curvagen-valhalla#15](https://github.com/Lazark0x/curvagen-valhalla/issues/15) (wayfinder map [#4](https://github.com/Lazark0x/curvagen-valhalla/issues/4)).
- **Spec:** ADR-0041 as amended 2026-09-07 (`docs/curvagen/adr/0041-roundtrip-v4-loop-quality-gate-v2.md`).
- **Scope:** production tooling and the shipped engine — no new algorithm, no new measurement. Everything the ladder measured with scratch scripts now lives in `tools/loopqual`, and the engine that was measured is the engine the defaults now build.
- **Not in scope (the cutover, still fog on the map):** the `FINGERPRINT_VERSION` bump in the orchestrator, re-enabling GitHub Actions on this fork for the amd64 image, the tile rebuild question if the twin map ever becomes a `TaggedValue`, and the deploy itself.

## 1. The engine: `proto/v4-p2.1` d, as the default

The v4 commit set lands the prototype tree (`proto/v4-p2.1` @ `f4a50bdbb`, engine code) on `curvature-costing` and **flips the defaults in `src/thor/worker.cc` to P2.1's `d` configuration** — the one ADR-0041 §Amendment 4 names and the one Gate v2 passed. The alternative, leaving the knobs off and setting them in `curvagen-meta/deploy`, was rejected: a knob that has to be set to get the measured behaviour is a knob that will one day not be set, and the fork has no CI to catch it (Actions are disabled here). Every knob is still a knob — setting it back reaches v3 / P1 / P2 behaviour for a bisect.

| knob | was | v4 | why |
|---|---|---|---|
| `roundtrip_pair_pass` | false | **true** | the Suurballe pair pass as the selection stage (P2) |
| `roundtrip_pair_bridge` | true | **false** | bridging measured dead (P2 §5: stubs) |
| `roundtrip_pair_leg_sharing` | false | **true** | per-leg forward-sharing test at selection (P2.1) |
| `roundtrip_pair_leg_sharing_frac` | 0.5 | **0.35** | variant c/d's threshold |
| `roundtrip_pair_built_keys` | false | **true** | bank keyed on the BUILT loop, not the pair |
| `roundtrip_pair_leg_relax` | false | **true** | the relaxation ladder — what keeps K = 12 |
| `roundtrip_pair_relaxed_last` | false | **true** | relaxed loops rank behind strict ones |
| `roundtrip_pair_rescue_last` | false | **true** | rescue-built loops rank behind pair-built ones |
| `roundtrip_pair_eval_total` | 0 (off) | **1200** | one evaluation budget per request — v0 OOM-killed the engine without it |
| `roundtrip_pair_eval_cap` | 600 | **1200** | same budget at the rung level |
| `roundtrip_pair_relax_eval_cap` | 0 | **150** | fresh evaluations per relaxation rung |
| `roundtrip_xcand_penalty` | false | **true** | prod already runs it |
| `roundtrip_xcand_strength` | 0.5 | **0.2** | prod's value (ADR-0039) |
| `roundtrip_gate_refill_budget` | 0 | **2** | the P1.1 knee |
| `roundtrip_fallback_rungs` | true | **false** | the P1.1 knee |

Checked against the measured run's own config (`/tmp/v8003-p21-d.json` in `rt-p1-build`): the shipped defaults are that file, knob for knob, minus `roundtrip_stage_timing` (a measurement knob, still off).

**Checked on geometry, not just on config.** The round-trip action is deterministic for a given binary, configuration and seed, so the built engine — started on a config with *no* `roundtrip_*` keys at all — was replayed against 32 saved corpus-v2 requests from the decision run (blocks A, B and C, 384 loops) and served **byte-identical shapes** every time (`~/.curvagen-scratch/v4build/replay.py`). Gate v2's reading of `p2-1-d` is therefore a reading of this build.

## 2. Provenance leaves the engine (ADR-0041 §7)

`TripRoute` gains a fork-local `CurvagenProvenance` sub-message (tag 100, `proto/descriptors/trip.proto`); `roundtrip_impl` fills it per candidate at serialization; the valhalla JSON serializer writes it inside each route's `trip` object as `"provenance"`. Additive — no other action sets it, and the orchestrator drops unknown fields, so no app-contract change and no `FINGERPRINT_VERSION` consequence of its own.

```json
"provenance": {"builder": "pair", "rung": 0, "tier": 0, "relaxed": 2,
               "gated": false, "bridges": 0, "full_repair": true}
```

`builder` is `pair` / `rescue` / `route_leg` (a `rescue` flag was added to the candidate rather than inferring it from `!pair_built`). D4 ("was this a Fallback Loop") was a geometric guess before this field (blind-spots §5, M11); it is a read now, and the served-tier check reads `tier` / `gated` directly.

**Verified end to end** on the shipped defaults: a 40 km Vračar ask returns twelve candidates whose `provenance` matches the engine's own per-slot ledger line (`roundtrip pair-leg: slots=0:0/1/0 … 8:2/1/0 9:3/1/0 10:3/1/0 11:2/1/0`, rung/pair-built/tier) exactly — slots 8–11 relaxed 2/3/3/2, everything pair-built, tier 0. The harness lands it as `prov_builder` / `prov_rung` / `prov_tier` / `prov_relaxed` / `prov_gated` / `prov_bridges` / `prov_full_repair` in `loops.jsonl` (`results/v4-provenance-smoke/`).

## 3. Metrics v2 in `tools/loopqual` (ADR-0041 §8)

`metrics.py` is version **v2**: the Retrace family (D1 same-pavement runs at r = 10 m, D1L near-mirror runs at r = 25 m, D4 reuse metres outside the Start Exemption), the **switchback-aware** near-mirror rule, the ring counter with the **fixed** overlap guard (D3), self-crossings (D3b), `shadow_frac_loop`, and the served-surface read of bank distinctness plus its per-leg split. Retired with the ADR: the exempt-corridor meter (D2) and the distance-lobe meter (D5). `LQ_D1B_LEGACY=1` restores the pre-2026-09-07 near-mirror read for re-reading old numbers.

**Byte-parity with the scratch detectors — the whole point of the port.** The ported code was run over the same saved responses the `lqbs_*` scripts read and compared field by field:

| run | loops compared | mismatched fields |
|---|---|---|
| Baseline v2 (`census-v2-b4f514d7f`) | 6 622 | **0** |
| prod bracket (`census-v2-p2-baseX`) | 6 621 | **0** |
| P2.1 d (`p2-1-d`) | 6 624 | **0** |

19 867 loops, every ported scalar identical. The scratch scripts are superseded; nothing in this repo imports them any more.

Two harness changes came with it: the analysis pass runs in a process pool (the detector bank costs ~75 ms per loop — 8 minutes single-core on corpus-v2), and `loopqual reanalyze --run <dir> [--out <dir>]` re-reads a saved run's responses with the current metrics without firing anything. Baseline v2 is pinned as `results/baseline-v2/` (responses symlinked to the census run) and the prod-config bracket as `results/baseline-v2-prod-bracket/`.

## 4. `gate_v2.py` — ADR-0041 as amended, executable

`tools/loopqual/gate_v2.py <baseline_v2> <candidate> [--bracket DIR]… [--cutover]` prints the three tiers on the Served Surface (blocks A+B, slots 0–5, c0.5/0.7/1.0) and exits non-zero on any blocking FAIL. Two baselines, because the ADR holds two things: **Baseline v2** (the census run) for the absolutes and the quality ratchets (T1, T5, T6), and one or more same-session **prod-config brackets** for the configuration-sensitive ones (T2, T3, T4) — `--bracket` repeats, and T3 reads the pooled p50, which is how the P2.1 session read it. `gate_v1_proto.py` is marked retired in its own docstring and stays as the ADR-0037 record — the v1.x thresholds and the runs judged by them remain readable, and nothing should be gated on it again.

Run on Baseline v2 vs the P2.1 d build with brackets A and B, the gate reproduces the amended ADR table to the decimal:

|---|---|---|
| R1 Retrace family, served | 43.9 % → ≤ 5 % | 43.9 % → **2.0 %** PASS |
| R4 fills | 550/552 → 552/552 | same |
| T2 Served-Surface Distinctness | prod 0.3171 / 11.6 %, bars ≤ 0.3488 / ≤ 16.6 % | **0.3370 / 13.8 %** PASS |

## 5. Serving mode re-pinned to contract 3.7.1

`runner.py::build_request` sent `startPoint` as an array and `metrics.py::Loop.from_serving_route` read a pre-3.0 `routes[].paths[0].points` 3D polyline — the shape has not existed on the wire since the API v-next redesign, so `--serving` 422'd on every request. Both now follow `curvagen-orchestrator/openapi.json` 3.7.1: `startPoint` is a `LonLat` object, the response is `{serveId, candidates[]}` with a 2D polyline6 `geometry` and metre `distance`. The engine-mode leg boundary still does not exist in the served DTO, so the seam stays derived (farthest point) in this mode.

## 6. Gurka — 53 green on the shipped defaults

`gurka_roundtrip_audit` 28/28 · `gurka_motorcycle_roundtrip` 22/22 · `gurka_roundtrip_distinctness` 3/3 — the P2.1 suites' 51 plus two provenance pins: `V4a` (every served candidate carries `curvagen_provenance`, the builder is `pair` or `rescue` with the pair pass on, and the object reaches the JSON) and `V4b` (with the pair pass off every builder reads `route_leg`).

Flipping the defaults broke eight tests, and every one of them was a test inheriting a configuration rather than stating one: on maps this small a different selection stage serves a different candidate, so the P1 / P1.1 mechanism under test was masked. Each pre-pair-pass fixture now calls `pin_pre_pair_pass(map)` (pair pass off, xcand off, refill budget 0, fallback rungs on) — the configuration those tests were written against — while the P2 / P2.1 suites turn the pair knobs back on themselves. One real fixture bug came out of it: `G2_ReturnRidesTheOppositeCarriageway` hard-coded the turnaround node when discounting the seam disc, so it read 0 m the moment the engine chose a different turnaround; it now reads the seam off the served route.

## 7. What the cutover still owes

- `FINGERPRINT_VERSION` in `curvagen-orchestrator/crates/cache/src/key.rs` is **4** today; v4 changes route output, so the cutover bumps it to 5 in the same commit as the deploy (the FINGERPRINT rule, `docs/curvagen/extension-api.md`).
- **Re-enable GitHub Actions on this fork** (Settings → Actions): the floating `ghcr.io/lazark0x/valhalla-curvature:amd64` tag is still the July `b4f514d7f` build because Actions are disabled, and the deploy consumes the CI-built amd64 image.
- The twin/parallel sidecar is built at engine start (4.5 s, 7 MiB); if it ever becomes a build-time `TaggedValue`, that is a tile rebuild and ships with the tiles.
- Baseline v3 = v4's own production-equivalent reading, after which T3 returns to ≤ 1.10× (ADR-0041 amendment 2), with the debt line (arc canonical-id caching, degree-2 folding, the rescue-build share) as v4.x items.

## Appendix — reproduction

```bash
# metrics v2 over a saved run (no requests fired), and the pinned baselines
cd tools/loopqual
./loopqual reanalyze --run results/census-v2-b4f514d7f --out results/baseline-v2
./loopqual reanalyze --run results/census-v2-p2-baseX  --out results/baseline-v2-prod-bracket
./loopqual reanalyze --run results/p2-1-d

# the gate, as ADR-0041 reads it
python3 gate_v2.py results/baseline-v2 results/p2-1-d \
  --bracket results/census-v2-p21-baseA --bracket results/census-v2-p21-baseB --cutover

# the engine, on its shipped defaults (no roundtrip knobs in the config at all)
docker exec -d rt-p1-build /tmp/start_engine.sh v8003-v4defaults.json v4probe
./loopqual run --engine http://localhost:8003 --corpus corpus-smoke-v1.yaml \
  --out results/v4-provenance-smoke/ --no-way --engine-note "v4 shipped defaults"

# gurka
docker exec rt-p1-build bash -lc 'cd /src/valhalla/build && make -j4 \
  gurka_roundtrip_audit gurka_motorcycle_roundtrip gurka_roundtrip_distinctness && \
  for t in gurka_roundtrip_audit gurka_motorcycle_roundtrip gurka_roundtrip_distinctness; do \
  ./test/gurka/$t --gtest_brief=1; done'
```

Parity harness: `~/.curvagen-scratch/v4build/parity.py` (local rig; compares `metrics.analyze_loop_v2` against the scratch `lqbs_*` jsonl field by field).
